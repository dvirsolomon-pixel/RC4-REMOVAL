The RC4 deadline already passed. The cleanup didn't.

Microsoft made AES the Kerberos default for accounts without an explicit setting in April 2026, and removed the rollback switch in July 2026. NTLMv1 restrictions followed in October 2026, and network NTLM is planned to be off by default in the next major Windows Server release. If any of these look familiar, you're in the cleanup phase:

Logons or services fail with KDC events 14 / 16

The account has no AES keys because its password predates AES support.

The requested etypes were 18 17. The accounts available etypes were 23.

KDCSVC events 201–209 on your DCs

Audit and enforcement events from the CVE-2026-20833 rollout point at accounts and clients still asking for RC4.

Microsoft-Windows-Kerberos-Key-Distribution-Center · KDCSVC

"Temporary" RC4 workarounds that became permanent

Accounts set to explicit RC4 just to silence errors keep working and keep the risk. This is hidden auth debt.

msDS-SupportedEncryptionTypes = 4 or 28 (RC4 still allowed)

NAS, Linux and Java apps stopped authenticating

Appliances joined years ago with an empty encryption-type attribute or RC4-only keytabs.

4769 · Ticket Encryption Type 0x17 (RC4-HMAC)

Free tools are good at finding these problems. Fixing them safely, with validation and rollback, has mostly been left to expensive enterprise platforms. KerbShift closes that gap.

How it works

Four steps, in the order that keeps production running.

  1. Audit

    List computer and user accounts with RC4 enabled or no encryption type set (the KDC treats null as RC4 risk). Export a CSV baseline with OS, last logon, SPNs and password age.

  2. Safe fix

    Move one account, then many, to AES128 + AES256 (24). An OS gate refuses legacy systems that can't do AES, and unknown OS versions are skipped by default.

  3. Rollback

    Something broke? Restore RC4 on that single account in one step while you fix the root cause, such as a password reset or keytab refresh.

  4. Report

    Every write is read back from AD and logged with before / after / expected values. Re-export the CSV as evidence for your client, manager or auditor.

FAQ

Isn't it too late? Enforcement already happened.

That's exactly why. Enforcement didn't remove RC4 everywhere. Explicit RC4 settings are still honored, and accounts without AES keys still fail. KerbShift helps you find and fix what's left, then prepares you for NTLM, which is next on the same path.

Which value does it write?

msDS-SupportedEncryptionTypes = 24 (AES128 + AES256). It's the safe universal target. 56 adds the AES256-SK bit and requires DCs patched in November 2022 or later; you can opt in by changing one variable.

Does it touch krbtgt?

No, intentionally. krbtgt encryption depends on its password state, not on this attribute. The README explains how to handle it: reset twice, at least 10 hours apart, after everything else is remediated.

What do I need to run it?

PowerShell 5.1+, the ActiveDirectory module (RSAT or a DC), and rights to modify msDS-SupportedEncryptionTypes on the target OUs.

Can MSPs use the free edition for client work?

Yes. Community is MIT licensed, so commercial use is allowed. The planned MSP edition adds multi-client management and white-label reporting on top.
