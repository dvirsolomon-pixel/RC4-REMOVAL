Free & open source · Windows

Take stock of the AI on every Windows machine.

AI Stocktake is a free PowerShell agent that shows what AI is running across your fleet: AI apps, browser extensions, coding agents, MCP servers, risky agent permissions, secrets agents can reach, and exposed local LLMs. You get one offline HTML report. It never reads prompts.

The problem

AI agents now have shell access, tokens and your files, and you can't see them.

Coding agents and MCP servers install per-user, read config files full of API keys, and can run commands. Network tools see traffic to chatgpt.com. They don't see what runs locally on the endpoint. These incidents are public:

September 2025

A malicious MCP server on npm

One version of the postmark-mcp package added a hidden BCC, so every email sent through the AI assistant was copied to an outside address.

Read Snyk's analysis
August 2025

Malware that used local AI CLIs to steal secrets

In the Nx "s1ngularity" supply-chain attack, the malicious packages looked for locally installed AI coding CLIs such as Claude, Gemini and Amazon Q, and prompted them to search developer machines for credentials.

Read GitGuardian's analysis
2026 report

Secrets sitting in MCP config files

GitGuardian's State of Secrets Sprawl 2026 reports 24,008 unique secrets found in MCP configuration files on public GitHub. The same files sit on your users' laptops.

What it finds

One scan, seven layers of AI on the endpoint.

Detection rules live in an open, community-maintained catalog, so new tools and changed config paths can be added with a pull request.

AI apps

Desktop AI apps and local runtimes, including per-user AppData installs that standard inventory often misses.

Browser extensions

AI extensions in Chrome, Edge, Brave and Firefox, with their requested permissions.

Coding agents

Claude Code, Cursor, GitHub Copilot, Gemini CLI, Windsurf and more, wherever they're installed.

MCP servers

Every configured MCP server: the command it runs, its package source, and whether the version is pinned.

Risky permissions

Auto-approve modes, unrestricted shell access, and agents running with local admin rights.

Reachable secrets

API keys and tokens in agent configs and env files. It reports the type and a one-way fingerprint, never the value.

Exposed local LLMs

Ollama and LM Studio listening on all interfaces instead of localhost only.

Privacy-first

An inventory, not a surveillance tool.

AI Stocktake reads installed software and configuration. The code is open, so your security team and works council can check exactly what it collects.

What it collects

  • Names and versions of AI apps, extensions and agents
  • MCP server definitions: command, package and pinning
  • Risky settings, such as auto-approve or shell access
  • For secrets: the type (for example "GitHub token") and a one-way fingerprint, so you can tell when the same key appears on several machines
  • Listening ports of local LLM runtimes

What it never collects

  • Prompts, chat history or AI responses
  • Secret values in plaintext
  • File contents, browsing history, keystrokes or clipboard
  • Anything sent anywhere by default. The Community edition runs fully offline
  • Usernames, if you turn on privacy mode (only the device name is kept)
How it works

Run it. Read the report. Then scale it.

  1. Run

    Run the PowerShell module on one machine, or deploy it to the fleet with an Intune Remediation, a platform script, GPO or a scheduled task. It runs in user mode, with no driver and no installer.

  2. Report

    Get a self-contained HTML report (plus JSON) with findings ranked by severity and a short note on how to fix each one. It works without an internet connection.

  3. Fleet dashboard Coming soon

    Optionally send results to a hosted dashboard: every device in one view, history, and alerts when something new appears.

# Download the module from the latest GitHub Release, then:
Import-Module .\AIStocktake.psd1
Invoke-AIStocktake -OutputPath .\ai-stocktake-report.html

Command names are from the planned v0.1 release. Check the README on GitHub for the current instructions.
